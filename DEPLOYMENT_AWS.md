# Plethora ERP — Zero-Docker AWS Deployment & Team Workflow (`af-south-1`)

This guide covers deploying **Plethora ERP** (`apps/web` and `apps/api`), **Meta WhatsApp Cloud API (v26.0)**, and the **self-hosted free `llama3.3:3b` AI model (Ollama)** on **AWS (`af-south-1` Cape Town)** with **zero Docker** anywhere in local development, CI/CD, or production.

---

## 1. Architecture Summary

- **Compute (`plethora-app` EC2 Auto Scaling Group)**: Ubuntu 24.04 LTS ARM64 (`t4g.medium`) running Node.js 24, native `chromium` (for Puppeteer PDFs), and `systemd` services (`plethora-api` on `:3001`, `plethora-web` on `:3000`).
- **Free AI Model (`plethora-ollama` EC2)**: Internal ARM64 Graviton (`m7g.large`, 8 GB RAM) running Ollama natively (`ollama.service`) with `llama3.3:3b` on a 30 GB gp3 EBS volume, reachable privately at `http://ollama.plethora.local:11434`.
- **Database (`Amazon RDS`)**: PostgreSQL 16 (`t4g.small`) in private isolated subnets with automated backups (`btree_gist` compatible).
- **Object Storage (`Amazon S3`)**: Private uploads bucket (`STORAGE_DRIVER=s3`) accessed via EC2 IAM Instance Profile (no static AWS keys).
- **CI/CD**: GitHub Actions (`Production readiness` + `deploy-aws.yml` via OIDC) + AWS CodeBuild (`buildspec.ci.yml` / `buildspec.deploy.yml`) + AWS CodeDeploy (`appspec.yml`).

## 2. Initial AWS CDK Bootstrap & Deploy

1. **Request an ACM TLS Certificate** in `af-south-1` for:
   - `plethora.quickbophasecurity.co.za`
   - `api.quickbophasecurity.co.za`
2. **Bootstrap & Deploy CDK Stacks**:
   ```bash
   cd infra/aws-cdk
   npm ci
   npx cdk bootstrap aws://<ACCOUNT_ID>/af-south-1
   npx cdk deploy --all \
     -c githubOwner=<YOUR_GH_ORG_OR_USER> \
     -c githubRepo=<YOUR_REPO_NAME> \
     -c acmCertificateArn=<YOUR_ACM_CERT_ARN>
   ```
3. **Note the CDK Outputs**:
   - `AlbDnsName` -> Point `plethora.quickbophasecurity.co.za` and `api.quickbophasecurity.co.za` CNAME/ALIAS records in Afrihost DNS to this ALB DNS name.
   - `GitHubActionsRoleArn` -> Add as a GitHub Repository Variable named `AWS_GITHUB_DEPLOY_ROLE_ARN`.

## 3. Populate Runtime Secrets (AWS Secrets Manager)

Update `plethora-prod-app-secrets` in **AWS Secrets Manager (`af-south-1`)** via the AWS Console or a local secure JSON file (never paste secrets directly into shell history or git):

Required keys in `plethora-prod-app-secrets`:
- `JWT_SECRET` (random >= 32 chars)
- `JWT_REFRESH_SECRET` (different random >= 32 chars)
- `ENCRYPTION_KEY` (32-byte hex or >= 16 char passphrase)
- `CRON_SECRET` (auto-generated by CDK)
- `AI_ENABLED`: `"true"`
- `AI_BASE_URL`: `"http://ollama.plethora.local:11434"`
- `AI_MODEL`: `"llama3.3:3b"`
- `WHATSAPP_ENABLED`: `"false"` initially (set `"true"` after webhook verification)
- `WHATSAPP_PHONE_NUMBER_ID`, `WHATSAPP_WABA_ID`, `WHATSAPP_ACCESS_TOKEN`, `WHATSAPP_VERIFY_TOKEN`, `WHATSAPP_APP_SECRET`

## 4. Enable GitHub Branch Protection & AWS CodeBuild

1. Connect AWS CodeBuild to your GitHub repository in **AWS Console -> CodeBuild -> Settings -> Connections** (or authorize the GitHub OAuth/App connection once).
2. Apply the `main` branch protection rules from [.github/branch-protection-main.json](./.github/branch-protection-main.json):
   ```powershell
   ./scripts/configure-github-branch-protection.ps1 -Owner <YOUR_GH_ORG_OR_USER> -Repo <YOUR_REPO_NAME>
   ```
   This enforces:
   - Required checks: `verify`, `cdk-validate`, and `codebuild/plethora-pr-verify`.
   - Minimum 1 approving review + `CODEOWNERS` review + linear history (Squash/Rebase only).
   - No direct pushes or force-pushes to `main`.

## 5. Team Daily Engineering & Release Workflow (Zero Docker)

1. **Create a Feature Branch**:
   ```bash
   git switch main && git pull
   git switch -c feat/<ticket>-short-description
   ```
2. **Local Development (Native)**:
   - Start PostgreSQL locally and run `npm run dev:all` (`apps/api` on `:3001`, `apps/web` on `:3000`).
   - *(Optional AI testing)* Install Ollama natively on your workstation, run `ollama pull llama3.3:3b`, and set `AI_ENABLED=true` and `AI_BASE_URL=http://localhost:11434` in `apps/api/.env`.
3. **Database Schema Changes**:
   - Always generate Prisma migrations via `npm run db:migrate --workspace=api` (never `db:push`).
   - Ensure migrations are backward-compatible with currently running EC2 instances during rolling deploys.
4. **Local Verification Before Push**:
   ```bash
   npm run test:api
   npm run test:web
   npm run build:api
   npm run build:web
   ```
5. **Open a Pull Request to `main`**:
   - Complete the 11-Step Antigravity checklist in `.github/PULL_REQUEST_TEMPLATE.md`.
   - Wait for `Production readiness` (`verify` + `cdk-validate`) and AWS CodeBuild (`plethora-pr-verify`) to turn green, then obtain peer approval.
6. **Squash Merge & Automated Production Release**:
   - Squash Merge into `main`.
   - `deploy-aws.yml` triggers `plethora-main-deploy` in AWS CodeBuild, which:
     1. Takes a pre-deploy RDS snapshot.
     2. Runs `npm run db:migrate:deploy --workspace=api` inside the VPC (halting immediately if migration fails).
     3. Compiles `api` and `web`, zips the release bundle to S3, and triggers **AWS CodeDeploy** (`plethora-app-dg`) for a rolling EC2 update with `/health/ready` validation.
7. **Rollback**:
   - Re-deploy the previous `releases/plethora-<PREVIOUS_SHA>.zip` bundle in **AWS CodeDeploy -> Deployments -> Create deployment**, and restore the pre-deploy RDS snapshot if a schema rollback is required.

## 6. WhatsApp Cloud API (v26.0) Cutover & AI Verification

1. Verify `https://api.quickbophasecurity.co.za/health/ready` returns `200`.
2. In **Meta for Developers -> WhatsApp -> Configuration**, set Callback URL to `https://api.quickbophasecurity.co.za/webhook` and your `WHATSAPP_VERIFY_TOKEN`, then subscribe to `messages`.
3. Subscribe the app to WABA (`POST /whatsapp/subscription`) and verify `GET /whatsapp/health?connectivity=true`.
4. Set `WHATSAPP_ENABLED=true` in `plethora-prod-app-secrets` and run `systemctl restart plethora-api` (or trigger a deploy).
5. Verify the self-hosted `llama3.3:3b` model via authenticated `GET /ai/health`:
   - Expected: `enabled: true`, `reachable: true`, `configuredModel: "llama3.3:3b"`, `modelLoaded: true`.
