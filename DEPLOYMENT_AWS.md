# Plethora ERP - Zero-Docker AWS Deployment & Direct-to-`main` CD (`af-south-1`)

This guide covers deploying **Plethora ERP** (`apps/web` and `apps/api`), **Meta WhatsApp Cloud API (v26.0)**, and **Amazon Bedrock (`Kimi K3.1` - `global.moonshotai.kimi-k3.1`)** on **AWS (`af-south-1` Cape Town)** with **zero Docker** anywhere in local development, CI/CD, or production.

---

## 1. Architecture Summary

- **Compute (`plethora-app` EC2 Auto Scaling Group)**: Ubuntu 24.04 LTS ARM64 (`t4g.medium`) running Node.js 24, native `chromium` (for Puppeteer PDFs), and `systemd` services (`plethora-api` on `:3001`, `plethora-web` on `:3000`).
- **AI Model (`Amazon Bedrock` - `Kimi K3.1`)**: Serverless Moonshot AI **Kimi K3.1** (`global.moonshotai.kimi-k3.1`) invoked in `af-south-1` via the Bedrock Converse API using the EC2 Instance Profile IAM Role (`AllowBedrockKimiInference` - zero static API keys, zero idle EC2 cost).
- **Database (`Amazon RDS`)**: PostgreSQL 16 (`t4g.small`) in private isolated subnets with automated backups (`btree_gist` compatible).
- **Object Storage (`Amazon S3`)**: Private uploads bucket (`STORAGE_DRIVER=s3`) accessed via EC2 IAM Instance Profile.
- **CI/CD**: Direct-to-`main` Continuous Deployment via AWS CodeBuild (`plethora-main-deploy` using `buildspec.deploy.yml`) + AWS CodeDeploy (`appspec.yml`).

## 2. AWS CDK Bootstrap & Deploy

1. **Request an ACM TLS Certificate** in `af-south-1` for:
   - `plethora.quickbophasecurity.co.za`
   - `api.quickbophasecurity.co.za`
2. **Bootstrap & Deploy CDK Stacks**:
   ```bash
   cd infra/aws-cdk
   npm ci
   npx cdk bootstrap aws://<ACCOUNT_ID>/af-south-1
   npx cdk deploy --all --require-approval never
   ```
3. **Note the CDK Outputs**:
   - `AlbDnsName` -> Point `plethora.quickbophasecurity.co.za` and `api.quickbophasecurity.co.za` DNS records to this ALB DNS name.

## 3. Runtime Secrets & AI Configuration

Runtime secrets live in `plethora-prod-app-secrets` in **AWS Secrets Manager (`af-south-1`)**:
- `JWT_SECRET` (random >= 32 chars)
- `JWT_REFRESH_SECRET` (different random >= 32 chars)
- `ENCRYPTION_KEY` (32-byte hex or >= 16 char passphrase)
- `CRON_SECRET` (auto-generated by CDK)
- `AI_ENABLED`: `"true"`
- `WHATSAPP_ENABLED`: `"false"` initially (set `"true"` after webhook verification)
- `WHATSAPP_PHONE_NUMBER_ID`, `WHATSAPP_WABA_ID`, `WHATSAPP_ACCESS_TOKEN`, `WHATSAPP_VERIFY_TOKEN`, `WHATSAPP_APP_SECRET`

CodeDeploy (`scripts/codedeploy/application_start.sh`) injects Amazon Bedrock runtime variables automatically at service start:
- `AI_PROVIDER=bedrock`
- `AI_REGION=af-south-1`
- `AI_MODEL=global.moonshotai.kimi-k3.1`
- `AI_TIMEOUT_MS=15000`

## 4. Direct-to-`main` Daily Release Workflow (Zero Docker)

1. **Local Development (Native)**:
   - Start PostgreSQL locally and run `npm run dev:all` (`apps/api` on `:3001`, `apps/web` on `:3000`).
   - *(Optional AI testing)* Either authenticate AWS CLI (`aws login --region af-south-1 --profile Plethora-prod`) with `AI_ENABLED=true` and `AI_PROVIDER=bedrock`, or use local Ollama with `AI_PROVIDER=ollama`.
2. **Database Schema Changes**:
   - Always generate Prisma migrations via `npm run db:migrate --workspace=api` (never `db:push`).
   - Ensure migrations are backward-compatible with running EC2 instances during rolling deploys.
3. **Push Straight to `main` -> Live AWS Production**:
   ```powershell
   git add -A
   git commit -m "feat: your update description"
   git push origin main
   ```
   - GitHub webhook triggers `plethora-main-deploy` (`concurrentBuildLimit: 1`), which:
     1. Runs migrations, all API unit + PostgreSQL integration suites, `db:audit`, Web unit tests, production API/Web builds, and CDK synth against an ephemeral `plethora_test` DB (aborting safely if anything fails).
     2. Creates a pre-deploy RDS snapshot and applies `db:migrate:deploy` to live RDS.
     3. Bundles and uploads the release zip to S3, rolls out via AWS CodeDeploy (`plethora-app-dg`), and verifies both HTTPS endpoints.
4. **Check Live Deploy Status**:
   ```powershell
   npm run --engine-strict=false deploy:status
   ```
5. **Rollback**:
   - Re-deploy the previous `releases/plethora-<PREVIOUS_SHA>.zip` bundle in **AWS CodeDeploy -> Deployments -> Create deployment**, and restore the pre-deploy RDS snapshot if a schema rollback is required.

## 5. WhatsApp Cloud API (v26.0) & Bedrock AI Verification

1. Verify `https://api.quickbophasecurity.co.za/health/ready` returns `200`.
2. Verify Amazon Bedrock Kimi K3.1 via authenticated `GET /ai/health`:
   - Expected: `enabled: true`, `reachable: true`, `provider: "bedrock"`, `region: "af-south-1"`, `configuredModel: "global.moonshotai.kimi-k3.1"`, `modelLoaded: true`.
