# Plethora Brand Quick Reference

**Use this as the fast standard for product, design, development and marketing work.**

---

## Brand position

**Plethora is a workforce operations platform built specifically for private security companies.**

It connects:

**People → Sites → Posts → Shifts → Attendance → Approvals → Payroll → Reporting**

Plethora is an **operational system of record**, not a generic HR app.

---

## Primary brand line

> **Every post covered, every hour accounted for.**

Supporting line:

> **From the gate to the payslip.**

Campaign line:

> **Cover the post. The rest follows.**

---

## Core value proposition

**Know what is happening across every site, connect actual work to accurate payroll, and keep a reliable operational record without rebuilding information across spreadsheets, messages and separate systems.**

---

## Brand personality

Plethora should feel:

- Operational
- Dependable
- Disciplined
- Confident
- Intelligent
- Practical
- Human

It should **not** feel playful, military, aggressive, futuristic, consumer-fintech-like or like generic HR software.

---

| Role | HEX | Usage |
|---|---:|---|
| Signal Orange | `#F97A08` | Active, live, attention, focus, selected |
| Deep Orange | `#A8480A` | Accessible orange text / deep signal |
| Orange Wash | `#FFF6EC` | Signal background |
| Graphite | `#171A1F` | Chrome, structure, primary text |

| Canvas | `#F5F6F8` | App background |
| Paper | `#FFFFFF` | Main work surface |
| Success Green | `#0E8A5F` | Covered, approved, complete, on duty |
| Error Red | `#C42B1C` | Genuine errors / destructive states |

### Colour rule

> **Orange is a signal, not wallpaper.**

Do not make every CTA, card or background orange.

---

## Typography

### Display / Headings
**Space Grotesk**

Use for:
- H1–H3
- page titles
- marketing headlines
- major metrics

### UI / Body
**Archivo**

Use for:
- body copy
- navigation
- tables
- forms
- controls
- documents

### Operational / Data
**JetBrains Mono**

Use for:
- times
- shift codes
- IDs
- audit values
- operational labels
- section eyebrows

Do not use JetBrains Mono for general body text.

---

## Geometry

```text
Default radius: 8px
Large radius:   14px
Small radius:   4px
Pill/full:      badges and chips only
```

Avoid overly rounded consumer-app styling.

---

## UI principles

1. **Operational clarity over decoration**
2. **Orange means something**
3. **State must always be clear**
4. **Dense without becoming confusing**
5. **The duty board is the visual model**
6. **One hierarchy, one vocabulary**
7. **Primary actions are deliberate**
8. **Motion communicates change, not decoration**

---

## Status language

- Orange = live / selected / waiting / attention
- Green = covered / approved / complete / on duty
- Red = error / critical failure / destructive
- Graphite = structure / neutral / inactive
- Blue = information only

Never rely on colour alone. Pair colour with labels, icons or shapes.

---

## Logo

Keep the existing Plethora logo mark and wordmark. Do not redesign it casually.

Canonical asset direction:

- Horizontal dark version
- Horizontal light version
- Standalone mark
- Monochrome dark/light marks
- Favicon
- App icon

Existing standalone mark: orange rounded square with two opposing white triangular forms meeting in the centre.

Do not:
- stretch
- rotate
- add glow/shadow
- recolour randomly
- change the geometry
- add gradients

## Photography

Use real South African private security environments:

- guards
- supervisors
- sites
- control rooms
- warehouses
- hospitals
- estates
- retail centres
- managers reviewing operations

People should look competent, calm, professional and realistic.

Avoid:
- guns as the focal point
- police/military aesthetics
- cyberpunk visuals
- generic American security imagery
- fake holographic technology

## Graphic language

Use visual inspiration from:

- duty boards
- roster grids
- shift timelines
- site/post layouts
- coverage indicators
- attendance records
- status spines
- operational data

Core visual idea:

> **People + sites + shifts + time + accountability.**

---

## Brand voice

Plethora should sound like an experienced operations partner.

Write:
- clearly
- confidently
- concisely
- practically
- professionally

Prefer:

**“See uncovered posts before the shift starts.”**

Avoid:

**“Revolutionise your workforce through next-generation intelligent optimisation.”**

Use concrete terms such as:

**guard, site, post, shift, roster, attendance, timesheet, approval, payroll, incident, report.**

## Website alignment rule

The **product design system is canonical**.

Future landing-page work should migrate toward:

- `#F97A08` instead of `#FF9800`
- `#171A1F` graphite instead of plum-black
- Space Grotesk / Archivo / JetBrains Mono instead of the separate landing-page font stack
- restrained 8px/14px geometry instead of default pill styling

Preserve strong operational storytelling such as handovers, timelines and roster-to-payroll flow.

---

## Do

- Keep interfaces structured
- Use graphite for authority
- Use orange sparingly
- Use green for positive operational state
- Show real security operations
- Keep terminology consistent
- Make state readable at a glance
- Use product screenshots and operational diagrams in marketing

## Don't

- Flood layouts with orange
- Add random gradients
- Mix fonts or icon families
- Use military/tactical visual language
- Use heavy glow/shadow effects
- Use generic HR language
- Use overly rounded consumer UI
- make exaggerated compliance or automation claims

---

## Final test

Before approving a Plethora design or message, ask:

**Does it communicate security operations, people, sites, shifts, time, accountability or payroll — and does it feel trustworthy to management while remaining clear to a guard?**

If yes, it is likely on-brand.
